# ChatGPT Switch 用户操作指南

> 本文使用“官方模式”和“API 模式”描述功能。当前界面为兼容旧版本，部分按钮仍显示“账号态”或“中转站”。以界面实际按钮和 [Release Notes](https://github.com/mingisrookie/codex-switch/releases/latest) 为准。

## 1. 开始前

1. 从 [GitHub Releases](https://github.com/mingisrookie/codex-switch/releases/latest) 下载 `codex-switch.exe`。
2. 安装 ChatGPT Desktop，并先在其中完成官方账号登录。
3. 关闭不需要的 ChatGPT Desktop 窗口；如果某项本地数据操作要求关闭相关写入程序，请按界面提示处理。
4. 首次使用会话迁移、合并、恢复或清理前，先在应用内创建完整备份。

项目只支持 Windows x64。Release 页面提供稳定版；仓库 `main` 的开发中功能不等于已发布功能。

## 2. 配置官方模式

1. 打开 ChatGPT Switch 的“运行态”页面。
2. 确认页面已识别本机的官方登录状态。
3. 点击 **“保存当前账号态”**。

这一步会保存用于切换的受管官方配置，不会要求你退出 ChatGPT，也不会把登录 token 显示在页面中。

## 3. 配置 API 模式

1. 在 API 模式卡片点击 **“配置 API 中转站”**。
2. 输入你有权使用的 Base URL、模型名和 API Key。
3. 应用不会单独探测中转站连接状态；请确认服务地址、模型和 Key 后直接切换，实际可用性以切换后的 ChatGPT 请求结果为准。
4. 点击 **“保存中转站”**。

Base URL 应使用可信的 HTTPS 服务；非本机 HTTP 地址会被拒绝。首次保存必须填写 API Key。已保存且服务来源未变化时，后续可以留空以继续使用已加密保存的 Key。

## 4. 切换模式

### 切到 API 模式

1. 确认 API 模式配置正确。
2. 点击 **“切换到中转站”**。
3. 在切换进度窗口中等待操作结束。
4. ChatGPT Desktop 会被关闭并在完成后尝试重新打开。

API 模式下，你的新请求会发往所配置的 API 服务。该服务的可用性、额度、费用和数据规则由服务提供方决定。

### 切回官方模式

1. 点击 **“切换到 ChatGPT 账号”**。
2. 等待切换进度窗口完成。
3. ChatGPT Desktop 重新打开后继续使用官方请求方式。

切换失败时先不要重复操作。保留错误信息，使用“诊断”面板导出本次诊断，必要时创建备份后再排查。

## 5. 管理本机会话

在“会话”页面可以查看本机会话和共享会话池中的会话，按标题、ID、来源、更新时间等信息搜索、筛选和排序。

- **恢复可见：**把当前本机中已归档的会话恢复为可见状态。
- **会话合并与修复：**仅处理可安全判断为缺失、相同或完整延续的会话关系；不确定或冲突的内容会保留原副本，不会直接覆盖。
- **同步此会话：**若当前版本显示该按钮，可由你明确发起单个会话的连续性操作；不要把本机“已提交”理解成目标设备或服务必然已收到。

旧聊天记录不会被工具默认批量上传。已归档会话默认不参与自动处理；先恢复可见后再按界面提供的操作处理。

### v0.3 存储迁移提示

如果“存储”页面提示需要迁移，请先阅读页面中的预检、备份和恢复验证提示。迁移前应关闭会话写入程序，并选择有足够空间的备份位置。迁移和会话合并与修复不等于长期备份。

## 6. 创建和恢复完整备份

1. 在运行态页面的备份区域点击 **“创建完整备份”**。
2. 等待操作完成后确认该恢复点出现在列表中。
3. 恢复时先选择经过验证的恢复点，再点击 **“恢复备份”** 并完成页面内确认。

恢复会改动受管本地数据，应用会先建立必要的安全恢复边界。只删除你确定不再需要的已验证恢复点。

## 7. 诊断与更新

### 诊断

顶部“诊断”按钮可导出最近诊断；当某次操作带有操作 ID 时，也可选择 **“导出本次诊断”**。导出包默认使用 Windows 下载目录；若该目录不可用，界面会提供受控的备用位置，而不是任意写入路径。

诊断包经过脱敏，但在发送给他人前仍应检查内容，并且不要附带 API Key、登录 token、聊天正文或完整本地配置。

### 更新

应用可检查 GitHub 最新正式 Release。发现新版本时，点击 **“立即更新”**，等待下载、替换和重启完成。网络失败不会把现有模式切换功能变成不可用。

如果应用内更新失败，请从 Release 页面手动下载 `codex-switch.exe`，并在替换前保留原文件和必要备份。

## 8. 常见操作建议

| 场景 | 建议 |
| --- | --- |
| 首次切 API 模式 | 先保存官方模式，再保存 API 模式；确认 Base URL、模型和 Key。 |
| API 服务更换 | 重新输入新服务对应的 API Key，不要沿用旧 Key。 |
| 切换失败 | 查看进度窗口，导出诊断；不要连续点击切换按钮。 |
| 会话需要整理 | 先创建完整备份，再使用会话合并与修复。 |
| 不想使用可选技能 | 不安装即可，核心模式切换不受影响。 |

有关 API Key、官方登录文件和本地数据的边界，请继续阅读 [安全与数据说明](SECURITY.md)。
